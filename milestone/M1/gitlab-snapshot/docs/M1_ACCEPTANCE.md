# M1 submission and review

M1 is the reusable core, initial 5×5/3×3 flow and actual asset-loading/compatibility foundation. It is not full-game completion. Keep the existing sample's compatible fields; list actual API conflicts before rewriting it.

| Deliverable | Required evidence |
|---|---|
| TypeScript/PixiJS complete source | Pushed commit and Draft MR, exact versions, real lockfile, clean install/build/run instructions |
| Reusable core | Runnable 5×5 initial flow and 3×3 from the same new core, geometry/game configuration and lifecycle evidence; not copied implementations |
| Asset inventory and actual playback | Scene/state to permitted art/Spine/textures/fonts/audio, source/export/runtime versions, rights/notices, available/missing originals and loading/playback recording; no unresolved required runtime asset blockers |
| Data boundary | Versioned synthetic input, identity/sequence/money formatting, skip/reload behavior, no client payout authority or hidden mock fallback |
| Review record | Commit/build/API/asset hashes, tested devices/browsers, reproducible findings, corrections/retest and remaining dependencies |

M1 is incomplete while required runtime art, Spine or audio is missing or has unresolved loading/playback/version-compatibility blockers. Recording a blocker in an inventory does not satisfy that requirement. This does not newly promise an unavailable original authoring project outside the agreed contract; distinguish that source-project boundary from required usable runtime assets.

The backend owner reviews the adapter/data boundary; reference reviewers check visuals/play/device behavior; Than owns client/assets/build. Consolidate findings against the same build. Name actual devices, orientations and browser versions with reviewers; a resized desktop window is not physical-device acceptance.

Source, initial flow and asset compatibility can be reviewed locally before the external API/final math is available. Full two-bonus audiovisual completion and final live API/math integration remain later agreed milestones. A loading screen, placeholder demo or passing fixture arithmetic alone is not complete delivery or automatic acceptance. Only the authorized client records milestone acceptance.
